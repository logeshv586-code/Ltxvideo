# RTX 4050 Demo Capture Guide

This folder is reserved for **real output generated by this repository on the stated local hardware**. Do not publish cloud-generated footage here and label it as RTX 4050 proof.

## Fast path: capture a hardware proof pack

After generating the demo clips on the actual RTX 4050 machine, run:

```powershell
python tools/capture_rtx4050_proof.py `
  --clip outputs/text-to-video.mp4 `
  --clip outputs/image-to-video.mp4 `
  --clip outputs/action.mp4 `
  --clip outputs/cartoon-story.mp4
```

The command intentionally **fails when an RTX 4050 is not detected**. On the target machine it writes:

```text
docs/demo/proof/
├── proof.json          # GPU/driver/OS/git SHA + clip SHA-256 hashes + shot template
├── diagnostics.txt    # output from python run.py --check
└── nvidia-smi.txt     # locally captured NVIDIA hardware report
```

Fill the four `shots` records in `proof.json` with the exact prompt/settings before publication. The proof pack should be committed or hosted alongside the demo so the hardware claim remains auditable.

## 1. Verify the machine first

```powershell
python run.py --check
```

The report should show the detected GPU, CUDA status, FFmpeg availability and model-cache state.

## 2. Capture four short examples

The target reel should contain:

1. **Text → Video** — General or Real World Studio.
2. **Image → Video** — animate a supplied reference image.
3. **Action Studio** — one clearly readable action beat and one camera move.
4. **Cartoon Story** — at least two connected scenes using continuity/reference anchoring.

Recommended first settings:

```text
Resolution: 384×224
Frames:     49 or 121
FPS:        30
Seed:       record the exact value
Steps:      record the exact value
```

If a 720p/1080p export is shown, label it as a **delivery resize**, not native diffusion resolution.

## 3. Required reproducibility data

For every clip, record:

| Field | Value |
|---|---|
| GPU | exact detected RTX 4050 string |
| System RAM | actual value |
| Studio | General / Real World / Action / Cartoon Story |
| Prompt | exact prompt used |
| Reference image | file name / none |
| Resolution | e.g. 384×224 |
| Frames | e.g. 49 |
| Approx. duration | e.g. 1.6 s |
| Seed | exact seed |
| Steps | exact steps |
| Guidance | exact value |
| Generation time | wall-clock time |
| Output file | relative path or hosted URL |
| SHA-256 | generated automatically by the proof tool |

## 4. Publication layout

```text
docs/demo/
├── README.md
├── rtx4050-demo.mp4          # only if repository size remains reasonable
├── preview.webp              # lightweight README preview if practical
├── demo-notes.md             # human-readable prompts/settings/timings
└── proof/
    ├── proof.json
    ├── diagnostics.txt
    └── nvidia-smi.txt
```

Large media can be hosted externally; keep the proof and notes in the repository.

## 5. README publication rule

Only replace the README's **Real RTX 4050 demo** placeholder after the footage has actually been generated on the target system. Put the media near the top of the README, show the exact hardware/settings beside it, and link to `docs/demo/proof/proof.json`.

## 6. Final verification

Before closing the tracking issue:

- every clip came from this repository on the captured RTX 4050 machine;
- the four workflow types are represented;
- prompt, seed, frames, resolution, steps, guidance and timing are filled in;
- delivery resizing is labeled honestly;
- the README contains the real preview/demo link.
